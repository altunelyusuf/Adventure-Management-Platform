## 🎯 IMPLEMENTATION DIRECTIVES

### Primary Directive
**Execute the Adventure Management Platform using AI LLM Development Agents following the 7-phase blueprint with strict adherence to Agile/Scrum methodology, UML best practices, and the ontology specification.**

### Key Principles for AI Agent Execution

#### 1. **Ontology-First Development**
- All development MUST align with the ontology specification in `ac-*.ttl` files
- Use ontology classes as domain models
- Implement ontology properties as data structures
- Follow ontology relationships for system integration

#### 2. **Phase-Sequential Execution**
- Execute phases in sequential order (1→2→3→4→5→6→7)
- Complete all sprints within a phase before proceeding
- Validate phase completion criteria before moving forward
- Maintain phase dependencies as specified

#### 3. **Sprint-Based Development**
- Follow 2-week sprint cycles
- Complete all tasks within sprint boundaries
- Conduct sprint planning, daily standups, and retrospectives
- Maintain sprint velocity tracking

#### 4. **Test-Driven Development (TDD)**
- Write tests before implementation
- Achieve 80%+ code coverage
- Implement unit, integration, and E2E tests
- Automate all test execution

#### 5. **Definition of Done (DoD)**
Every deliverable MUST meet:
- Code implemented and peer-reviewed
- Unit tests written and passing (80%+ coverage)
- Integration tests passing
- Documentation complete
- Security scan passed
- Performance benchmarks met
- Deployed to staging environment
- Product Owner acceptance received


### Story Point Estimation (Fibonacci)
- **1 point**: < 2 hours, trivial task
- **2 points**: 2-4 hours, simple implementation
- **3 points**: 4-8 hours, moderate complexity
- **5 points**: 1-2 days, complex feature
- **8 points**: 3-5 days, very complex
- **13 points**: 1 week+, epic-level (break down)

### Velocity Tracking
- **Target Velocity**: 40-60 points per sprint (8-person team)
- **Calculate**: Average of last 3 sprints
- **Adjust**: Based on team capacity and historical data

## 🎯 ACCEPTANCE CRITERIA TEMPLATE

Each user story MUST include:

### Functional Criteria
```
GIVEN [initial context/state]
WHEN [action is performed]
THEN [expected outcome]
```

### Non-Functional Criteria
- **Performance**: Response time < Xms
- **Security**: Authentication/authorization requirements
- **Usability**: UI/UX standards compliance
- **Accessibility**: WCAG 2.1 Level AA compliance
- **Scalability**: Handles X concurrent users

### Example
```
Story: User Registration

Acceptance Criteria:
1. GIVEN a new user on registration page
   WHEN they submit valid email and password
   THEN account is created and verification email sent

2. WHEN email is already registered
   THEN error message displayed "Email already exists"

3. Performance: Registration completes in <2 seconds
4. Security: Password hashed with bcrypt (cost factor 12)
5. Usability: Form validation provides real-time feedback
```
